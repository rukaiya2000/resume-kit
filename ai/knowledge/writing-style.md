# Resume writing style

## Bullets

- Start with a strong past-tense verb for past roles (Architected, Led, Cut, Automated). Present tense only for ongoing work.
- Shape: **what you did → how (tools the job cares about) → result with a number**.
- Keep every number exactly as written in the source: “30+ tenants”, “cut … by 80%”.
- One idea per bullet, ideally one line and never more than two (about 220 characters).
- Lead with the job description's language when it is the same thing: “REST APIs”, “tool calling”, “CI/CD”.
- No first person, no filler (“responsible for”, “worked on”, “various”, “cutting-edge”).
- Inline formatting the app understands: `**bold**` for one key term per bullet at most, `[label](url)` for links. Use sparingly.

## Technical Skills

- Order categories by how much the job cares about them; put the job's must-have skills first within each category.
- Rename a category if it helps scanning (“LLM & AI Engineering” for an AI role), but never move a skill into a category that misrepresents it.
- Drop skills that are irrelevant to this job when space is tight. Three sharp categories beat seven padded ones.

## Experience

- Keep the 3–5 bullets that best prove the job's requirements, most relevant first.
- Every role stays; hide one only if it is truly irrelevant and space is needed.

## Projects

- Pick 2–4 projects that best match the job; order by relevance, not date.
- Subtitle: short description plus tech stack in parentheses, e.g. `AI Voice Collections Agent (Python, FastAPI, SQLite)`.
- At most 3 bullets: the problem and what you built, the hardest technical decision, the result.

## One page

The app shrinks spacing and fonts to fit one page (down to its minimum). If an export is still over one page, cut in this order: least relevant project bullet → weakest experience bullet → least relevant skills → one project.
